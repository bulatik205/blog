# Пакеты & Структура

> Пакеты в go - это базовая единица. 

- Каждый файл должен начинаться с обьявления: 
```go
package {name}
```
- Пакет может быть исполняемым или библеотекой
- Исполняемый должен называться `main` и иметь функцию `main()`, как точку сбора приложения
- Экспорт внутри пакета:
```go
package mypkg

func Exported() {}   // доступна извне (заглавная буква)
func internal() {}   // доступна только внутри пакета
```
- Импорт пакетов:
```go
import (
    "fmt"                      // стандартная либа
    "github.com/user/repo/pkg" // внешний пакет с гита
    myalias "example.com/xyz"  // псевдоним
    _ "example.com/sideeffect" // только для побочных эффектов
    . "example.com/dotimport"  // импорт в текущее пространство имён
)
```

| Тип | Синтаксис | Значение |
|----|----|----|
| Алиас | `myalias "example.com/xyz"` | Дает название либе. Чтобы не писать `import j "encoding/json"` просто: `j.Marshal(...)`. Если два пакета называются одинаково - можно дать им алиас. Если имя пакета не связано с функцией, можно обьявить её явно  
| Пустой импорт | `_ "github.com/go-sql-driver/mysql"` | Нужен в основном для первичной инициализации. Но в коде к нему обратиться нельзя — имени нет |
| Импорт в текущее пространство имён | `. "example.com/dotimport"` | Все функции попадают в текущую зону видимости. Минус: появляется эффект "чёрного ящика" |

## Типичная структура

```
myproject/
├── go.mod
├── main.go              // package main
├── internal/            // код, недоступный извне модуля
│   └── auth/
│       └── auth.go      // package auth
├── pkg/                 // публичные переиспользуемые пакеты
│   └── utils/
│       └── utils.go     // package utils
└── models/
    └── user.go          // package models
```

### `internal/`

- Жёсткое правило компилятора, а не договорённость.
- Go запретит импортировать `myproject/internal/auth` из любого другого модуля. Ошибка компиляции, не «некрасиво», а именно нельзя.
- Смысл: код, который ты не хочешь делать частью публичного API. Можно смело рефакторить - никто снаружи не сломается.

### `pkg/`

- Это просто соглашение, никаких ограничений компилятора.
- Идея: _«этот код спроектирован так, что его можно вынести в отдельный модуль и импортировать в другом проекте»_.
- Подразумевается, что здесь нет завязки на конкретное приложение - утилиты, клиенты, библиотеки, хелперы общего назначения.

### `models/`

- Доменные типы именно проекта (User, Order, бизнес-логика).
- Переиспользовать в другом проекте не предполагается - он про это приложение.

## Правила

1. Один каталог = один пакет (кроме _test пакетов):

```go
// models/user.go
package models

// models/order.go
package models
```

```go
// models/user.go
package models

// models/order.go
package orders   // found packages models (user.go) and orders (order.go)
```

2. Имя пакета = имя последнего элемента пути импорта (по соглашению)

```go
// pkg/utils/utils.go
package utils
```

```go
// pkg/utils/utils.go
package helpers   // имя не совпадает с папкой
```

3. Пакеты в одном каталоге не могут иметь разные имена
4. Циклические импорты запрещены

```
Пакет A не может импортировать B, если B (напрямую или косвенно) импортирует A.
```

5. go.mod определяет модуль — набор связанных пакетов
